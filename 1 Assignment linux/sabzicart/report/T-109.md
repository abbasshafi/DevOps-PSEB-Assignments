## Part A Question 4
Command: systemctl --user cat sabzicart-api ; ls -l ~/sabzicart/webapp/start-api.sh
Answer: The ExecStart line is ExecStart=%h/sabzicart/webapp/start-api.sh, so the service runs /home/abbasshafi/sabzicart/webapp/start-api.sh (%h is my home folder). The cause is in the permissions:
-rw-r--r-- 1 abbasshafi abbasshafi 440 Oct 29 14:59 start-api.sh
The file has no execute (x) bit for anybody, so it cannot be run as a program.

## Part B Question 1
Command: cp -p app.conf app.conf.pre-T109 ; (change port = 9090 to port = 80 in app.conf) ; systemctl --user restart sabzicart-api ; systemctl --user status sabzicart-api ; journalctl --user -u sabzicart-api -n 8
Answer: Before editing I made a backup copy of app.conf. With port = 80 the service FAILED:
Active: failed (Result: exit-code)
Process: ExecStart=/home/abbasshafi/sabzicart/webapp/start-api.sh (code=exited, status=1/FAILURE)
The error in the logs:
PermissionError: [Errno 13] Permission denied   (raised by self.socket.bind(self.server_address) inside python's http server)
Why: ports below 1024 are "privileged" ports. Only root (or a program with a special capability) may listen on them, and the service runs as my normal user. That is why real websites use a proxy or root to get port 80, and why this practice site uses 9090 instead.
Fix: I put the file back (port = 9090, diff showed it identical to the backup), restarted, and checked:
is-active: active
curl http://localhost:9090 -> HTTP 200

## Part B Question 2
Command: mv app.conf app.conf.off ; systemctl --user restart sabzicart-api ; systemctl --user status sabzicart-api ; journalctl --user -u sabzicart-api -n 10
Answer: The service FAILED again, but in a different way:
Active: failed (Result: exit-code), Process: ExecStart=.../start-api.sh (code=exited, status=2)
The logs say:
SabziCart API starting on port        <- the port is empty
usage: python3 -m http.server [-h] [--cgi] [-b ADDRESS] ... [port]
python3 -m http.server: error: argument port: invalid int value: ''
sabzicart-api.service: Main process exited, code=exited, status=2/INVALIDARGUMENT
What went wrong: start-api.sh gets the port by reading the "port =" line from app.conf. With the file renamed, grep finds nothing, so PORT is empty and python is started without a valid port number. Compare the two failures: with port 80 the program started but the system refused the port (permission error, status 1); with the file missing the program never got a valid setting (invalid argument, status 2).
Fix: mv app.conf.off app.conf, restart, then is-active: active and HTTP 200.

Answer: After starting them all three are active. Yes, a service came back on its own: avahi-daemon. Its status shows
TriggeredBy: ● avahi-daemon.socket
which means a socket unit listens for requests and starts the service again as soon as something uses it (socket activation). cups also shows TriggeredBy: ● cups.path (a path unit can start it when print jobs arrive). cron has no TriggeredBy line, which is why it stayed down until I started it by hand. So stopping a service does not always keep it stopped.
