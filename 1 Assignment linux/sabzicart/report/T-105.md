## Part C Question 2
Command: sudo chown root:sz-dev /srv/sabzicart/dev && sudo chmod 2770 /srv/sabzicart/dev ; sudo chown root:sz-ops /srv/sabzicart/ops && sudo chmod 2770 /srv/sabzicart/ops ; sudo chown root:sz-support /srv/sabzicart/support && sudo chmod 2770 /srv/sabzicart/support ; sudo chown root:sz-staff /srv/sabzicart/common && sudo chmod 2775 /srv/sabzicart/common ; ls -l /srv/sabzicart
Answer:
total 16
drwxrwsr-x 2 root sz-staff   4096 Nov  1 11:02 common
drwxrws--- 2 root sz-dev     4096 Nov  1 11:02 dev
drwxrws--- 2 root sz-ops     4096 Nov  1 11:02 ops
drwxrws--- 2 root sz-support 4096 Nov  1 11:02 support
The "s" in the group permissions is the setgid bit (g+s), so new files get the folder's group. The 770 folders give the team group read+write and everyone else nothing. common is 775 with group sz-staff: all five users are in sz-staff (read+write), everyone else gets read only.

## Part C Question 4
Command: sudo -u sana touch /srv/sabzicart/ops/test-sana.txt ; sudo ls -l /srv/sabzicart/ops
Answer: -rw-r--r-- 1 sana sz-ops 0 Nov  1 11:02 test-sana.txt
The owner is sana, but the group is sz-ops. A new file normally gets the creator's primary group (sana). Because the ops folder has the setgid bit (the "s" in drwxrws---), new files inherit the folder's group instead. That way everyone in sz-ops can work on the file.
