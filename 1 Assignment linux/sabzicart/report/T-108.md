## Part A Question 4
Command: pgrep -a sabzi ; pgrep -af sabzi
Answer: pgrep -a sabzi printed nothing (exit code 1). Without -f, pgrep only matches the process NAME (the short program name, for example "yes" for the CPU hog), and "sabzi" is not in those names. The sabzi-... text is only in the full command line. pgrep -af sabzi matched and listed 39204 to 39209 and 39211 (and also the noisy-logger line, because its command line mentions the sabzicart path). man pgrep: -f makes pgrep match against the full command line instead of just the process name, and -a prints that full command line next to the PID.


## Part A Question 5
Command: kill 39204 ; top -b -n 1 | head -10
Answer: I stopped the CPU hog (sabzi-report-generator, PID 39204) with a normal kill (SIGTERM). Afterwards top no longer lists it, the CPU is 96.5% idle (before it was about 82.8% idle with the process at ~91-100%), and the load dropped.

## Part A Question 6
Command: pgrep -af noisy ; wc -l ~/sabzicart/logs/noisy.log ; sleep 10 ; wc -l ~/sabzicart/logs/noisy.log ; kill 39210 ; wc -l ... ; sleep 10 ; wc -l ...
Answer: noisy-logger (PID 39210) writes to /home/abbasshafi/sabzicart/logs/noisy.log (its full command line is: while true; do date >> ".../noisy.log"; sleep 0.5; done). Growing: 125 lines, then 145 lines 10 seconds later (about 2 lines per second). After kill 39210 the file stayed at 145 lines both times I counted, 10 seconds apart, so it stopped growing.

## Part A Question 7
Command: pgrep -af '^sabzi-worker' ; pkill -f '^sabzi-worker' ; pgrep -af '^sabzi-worker' || echo "workers gone"
Answer: I previewed first and the pattern matched exactly the 5 workers (39205 to 39209). Then one pkill stopped all five, and the second pgrep printed nothing ("workers gone"). The ^ makes the pattern match only command lines that START with sabzi-worker, so it can't hit anything else (like an editor with that name open).

## Part A Question 8
Command: kill 39211 ; pgrep -af '^sabzi-stubborn' ; kill -9 39211 ; pgrep -af '^sabzi-stubborn' || echo "stubborn gone"
Answer: The normal kill had no effect: sabzi-stubborn was still listed afterwards. Its command line is:
sabzi-stubborn -c trap "" TERM; while true; do sleep 1; done
trap "" TERM tells the shell to ignore the TERM signal (the signal a normal kill sends). SIGKILL (kill -9) cannot be caught or ignored by any process, so kill -9 stopped it ("stubborn gone").

## Part C Question 1
Command: sleep 600 (then Ctrl+Z) ; jobs ; bg %1
Answer: Ctrl+Z paused the foreground job:
[1]+  Stopped                    sleep 600
jobs listed it as Stopped. bg %1 continued it in the background:
[1]+ sleep 600 &

## Part C Question 2
Command: sleep 601 & ; sleep 602 & ; jobs
Answer:
[1]   Running                    sleep 600 &
[2]-  Running                    sleep 601 &
[3]+  Running                    sleep 602 &
The + marks the current job (the most recent one), and the - marks the previous one.

## Part C Question 3
Command: fg %2 (then Ctrl+C) ; jobs ; kill %1 %3 ; jobs
Answer: fg %2 brought "sleep 601" to the foreground and Ctrl+C stopped it, so jobs then showed only [1] and [3]. Then kill %1 %3 sent them the TERM signal. The next jobs still showed both as "Running" because the shell only reports a finished job a moment later; the messages arrived at the next prompt:
[1]   Terminated                 sleep 600
[3]-  Terminated                 sleep 602
